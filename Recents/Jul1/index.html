Top Stories • Week of June 22
01
Active Disclosure · Agent RCE Via Latest Hacking News · DevFortress

Four AI Coding Tools, Same Flaw, One Disclosure Week — Amazon Q Auto-Runs MCP Configs From Any Repo You Open

CVE-2026-12957CVSS 8.5


Amazon Q Developer automatically executed the .mcp.json / MCP server configuration embedded in any repository a developer opened — no prompt, no confirmation. Those servers launched as child processes that inherited the parent’s full environment: AWS credentials, API tokens, the lot. Clone a hostile repo, open it in your assistant, and it quietly runs the attacker’s tool server as you.


The bigger story is that Amazon Q was the third tool to disclose this exact pattern last week. Same root cause landed as CVE-2025-59536 and CVE-2026-21852 in Claude Code and CVE-2026-30615 in Windsurf — four tools, six named CVEs, one disclosure window. This is the direct sequel to Issue #5’s eBay MCP RCE and Issue #9’s “prompts become shells.”

Why It Matters for Vibe Coders
“Open a repo to look at it” is now a code-execution decision. The MCP config is the new package.json postinstall script — a file that runs on your machine with your secrets, just for browsing a project. If your workflow is “clone anything interesting and let the agent poke around,” you are the exploit.
Action Items
  • Update Amazon Q Developer, Claude Code, and Windsurf to the patched builds now.
  • Disable auto-loading of workspace/repo MCP configs; require manual approval per project.
  • Never open an untrusted repo in an AI tool that inherits your shell env — use a throwaway container.
  • Rotate AWS keys and API tokens that sat in the env of any tool you opened sketchy repos with.
02
Supply Chain · Self-Spreading Via The Hacker News · StepSecurity

The npm Worm Mutated Again — 20 Packages Poisoned in Under 3 Seconds, Secrets Exfiltrated Via Your Own GitHub Token

On June 24, an attacker pushed malicious versions of 20 npm packages in the Leo Platform ecosystem in a coordinated burst spanning less than three seconds. Every package carried an identical CI/CD attack toolkit that scrapes secrets from GitHub Actions runners, cloud credential stores, package registries, and password managers — then exfiltrates them through the victim’s own GitHub token.


It’s the latest limb of the Shai-Hulud / “Miasma” worm family we flagged around the SAP and Hugging Face incidents. Earlier in June it hit ~32 @redhat-cloud-services packages (~80K weekly downloads) by way of a compromised employee GitHub account pushing orphan commits with valid SLSA provenance. Legit signatures, malicious code.

Why It Matters for Vibe Coders
Provenance and “verified publisher” badges no longer mean safe — the attacker rode real accounts and real signing. And it self-propagates: one compromised CI run steals a token that publishes the next batch. A worm that spreads through your automation doesn’t need you to fall for anything twice.
Action Items
  • Pin exact versions and enable npm ci with a committed lockfile — no floating ranges.
  • Scope GitHub Actions GITHUB_TOKEN to read-only by default; gate publish behind manual approval.
  • Audit installs from the last two weeks against the Red Hat / Leo Platform IOC lists.
  • Move npm publish tokens to short-lived OIDC and rotate long-lived CI secrets now.
03
CISA KEV · Active Exploitation Via CISA · BleepingComputer

SimpleHelp Auth Bypass Added to CISA KEV — Dropping a Stealer That Specifically Hunts Developer & AI-Tool Tokens

CVE-2026-48558


CISA added a SimpleHelp authentication-bypass flaw to its Known Exploited Vulnerabilities catalog on June 29. The bug lets an unauthenticated attacker create highly privileged technician accounts on internet-facing SimpleHelp (OIDC) servers — instant admin on the remote-management platform. Roughly 1,000 vulnerable instances were exposed at disclosure.


Post-exploitation drops a JavaScript loader (“TaskWeaver”) and the new cross-platform Djinn Stealer (Windows/macOS/Linux) that, per BleepingComputer, focuses on developer credentials, AI-tooling tokens, and crypto wallets. That target list is basically this newsletter’s audience.

Why It Matters for Vibe Coders
Stealers have officially added “AI-tooling tokens” to the loot table next to browser cookies and wallets. Your OpenAI/Anthropic keys, npm tokens, and CI secrets are now first-class targets — and a KEV listing means this is being exploited right now, not theoretically.
Action Items
  • Patch SimpleHelp immediately and invalidate any unrecognized technician sessions.
  • Treat AI API keys like production secrets: vault them, don’t leave them in plaintext dotfiles.
  • Rotate credentials and API keys on any host touched by an affected SimpleHelp server.
  • Enforce MFA on your model-provider dashboards and set spend/usage alerts.

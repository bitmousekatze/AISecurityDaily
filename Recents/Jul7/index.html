Top Stories • Week of June 30
01
Zero-Click · Agent RCE Via Cato Networks · The Hacker News · SecurityWeek

"DuneSlide": Two Zero-Click Prompt Injections Break Cursor Out of Its Own Sandbox — And Cursor Initially Said That Wasn't a Bug

CVE-2026-50548CVSS 9.8  CVE-2026-50549CVSS 9.8


Cato AI Labs disclosed two independent flaws in Cursor — dubbed DuneSlide — that let a poisoned MCP response or web search result steer the agent into writing files outside the project sandbox, then escalate to full OS-level code execution. One abuses the working_directory parameter of the terminal tool to point commands at attacker-chosen paths; the other has the agent create a symlink inside the project that points outside it. No click, no confirmation — the victim just types an innocuous prompt that happens to ingest attacker-controlled content.


The timeline is the story: Cato reported both bugs on February 19 and Cursor rejected them on February 23, saying its threat model "does not account for MCP server misuse" — even via standard, innocuous integrations. Both were quietly fixed in Cursor 3.0 (April 2); everything before 3.0 is vulnerable. This is Issue #11's auto-exec saga wearing a new coat: last week the config was the payload, this week the content the agent reads is.

Why It Matters for Vibe Coders
The sandbox is a suggestion if the agent can be talked into redecorating outside it. Every MCP server you connect and every web result your agent ingests is now input to a machine that can write files and run terminals as you. "My editor's threat model doesn't cover that" — said the editor — is exactly why yours has to.
Action Items
  • Confirm you're on Cursor 3.0 or later — every earlier version carries both flaws.
  • Trim your MCP server list to ones you'd give shell access, because you effectively have.
  • Turn off auto-run/YOLO modes; keep a human approval gate on terminal and file-write tools.
  • Work on untrusted repos in a container or VM that holds zero real credentials.
02
Patch Wave · Dev Toolchain Via Cybersecurity News · GBHackers

JetBrains Patches a Critical Cluster Across Hub, YouTrack, Kotlin and Its IDEs — "Open a Malicious Project" Is Code Execution in GoLand

CVE-2026-56141CVSS 9.8  CVE-2026-50242  CVE-2026-56142


JetBrains shipped fixes for a pile of critical vulnerabilities across its on-premise ecosystem. The headliner: Hub account-restore codes were generated with a weak RNG, letting an unauthenticated attacker enumerate valid codes and take over any account — including admin. A second flaw allowed auth bypass via direct database access, and a third let attackers attach their own authentication details to existing accounts.


The IDE side is worse for individual devs: GoLand executed attacker-controlled logic from untrusted project configuration just by opening a project, Kotlin had unsafe deserialization in build-cache metadata that ran code during builds, and IntelliJ IDEA carried command injection through filename completion. Sound familiar? It's the same lesson as last week's MCP auto-exec: your IDE treats project files as trusted, and attackers noticed years before the vendors did.

Why It Matters for Vibe Coders
A compromised IDE isn't one machine — it's your source, your SSH keys, your API tokens, and your deploy pipeline in one seat. Between Cursor, JetBrains, and Issue #11's four MCP auto-runners, the score for the past fortnight is: every major way developers open code has shipped an "opening code runs code" bug.
Action Items
  • Update all JetBrains IDEs (IntelliJ, GoLand, PyCharm, WebStorm, Rider, etc.) and Kotlin toolchains now.
  • Self-hosting Hub, YouTrack, or TeamCity? Patch immediately — the Hub takeover needs no auth.
  • Audit Hub/YouTrack admin accounts and sessions for restores or logins you don't recognize.
  • Use per-project "trusted project" prompts honestly — don't reflex-click trust on cloned repos.
03
Supply Chain · Nation-State Via Threat-Modeling.com

North Korea's "PolinRider" Campaign Goes Multi-Registry — 108 Malicious Packages Across npm, Packagist, Go Modules and a Chrome Extension

The DPRK-linked campaign tracked as PolinRider was mapped this week at 108 malicious packages and 162 total artifacts: 19 on npm, 10 on Packagist, 61 Go modules, and a Chrome extension. Entry point is the long-running "Contagious Interview" playbook — fake recruiters send a take-home coding task whose repo or dependency tree pulls the malware in — plus compromised maintainer accounts publishing under real names.


This lands three weeks after the same country's Sapphire Sleet crew republished 140+ packages in the Mastra AI scope, and it closes the loop on a trend we've tracked since the Shai-Hulud worm coverage: supply-chain attackers no longer live on npm alone. If your lockfile spans ecosystems, so does your attack surface — Go and PHP devs don't get to skim this section anymore.

Why It Matters for Vibe Coders
The "npm problem" is now an every-registry problem, and the initial access is aimed straight at developers — a job offer, a take-home task, a repo you're told to run. Combine that with last story's "opening a project is code execution" and the take-home interview is a remarkably efficient exploit chain.
Action Items
  • Run recruiter take-home tasks in a disposable VM — never on the machine with your keys.
  • Adopt a minimum package-age policy (e.g. 7+ days) across npm, Packagist, and Go proxies.
  • Audit Go module and Composer dependencies too — scanning only package.json is half a scan.
  • Check installed browser extensions against your org's allowlist; the campaign shipped one.

After the worm season we've chronicled since May, the registry is finally killing its own postinstall footgun. Experts say it's not enough; it's still the best npm news this year.
